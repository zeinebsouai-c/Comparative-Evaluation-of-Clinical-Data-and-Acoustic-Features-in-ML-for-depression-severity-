# Multimodal depression severity prediction comparison: evaluation, interpretability, robustness

Predicting PHQ-9 depression severity from speech and clinical questionnaire data,
using the Lanzhou 2015 audio subset of the MODMA dataset.

The analysis compares what acoustic features can predict against what clinical
scales predict, and how much the two add to each other, with nested
cross-validation for the feature-reduction choice, robustness controls that
degrade the audio down to pure noise to check the acoustic signal is real, three interpretability methods that measure feature importance, and error analysis.

## Data

**Source:** MODMA (Multi-modal Open Dataset for Mental-disorder Analysis), collected
at Lanzhou University Second Hospital. This project uses only the
`audio_lanzhou_2015` subset: the audio recordings and the accompanying clinical
spreadsheet.

Data source: **Gansu Provincial Key Laboratory of Wearable Computing, Lanzhou
University, China.** Any work using this dataset must acknowledge that and cite:

> Cai, H., Gao, Y., Sun, S., Li, N., Tian, F., Xiao, H., Li, J., Yang, Z., Li, X.,
> Zhao, Q., Liu, Z., Yao, Z., Yang, M., Peng, H., Zhu, J., Zhang, X., Hu, X., &
> Hu, B. (2020). *MODMA dataset: a Multi-modal Open Dataset for Mental-disorder
> Analysis.* arXiv preprint arXiv:2002.09283.

**Contents:** 52 subjects: 23 with major depressive disorder, 29 healthy
controls, each with 29 recordings; 18 interview responses, 1 passage reading,
6 word-group readings and 4 picture descriptions. Recorded at 44.1 kHz / 24-bit
mono in a sound-treated room with ambient noise below 60 dB. Alongside these is a
spreadsheet of demographics and questionnaire scores (PHQ-9, GAD-7, CTQ-SF, LES,
SSRS, PSQI). PHQ-9 is the prediction target.


**Access:** request the dataset at http://modma.lzu.edu.cn/data/index/. Access
requires signing an End User License Agreement. Once you have it, place the files
as:

```
audio_lanzhou_2015/input/
    subjects_information_audio_lanzhou_2015.xlsx
    audio_lanzhou_2015_og/
        02010001/  02010002/  ...        one folder per subject
```

Everything else under `input/` (resampled audio, noise conditions) is generated by
the pipeline.

**What ships in this repository:** the code, and only those result tables that
contain no per-subject records:  metric tables, feature importances, SHAP
summaries, CV fold scores, plus openSMILE 3.0 under `tools/`.

**What does not, and why:** the MODMA EULA prohibits redistributing the dataset
or portions of it. That covers any table with one row per subject carrying their
diagnosis, PHQ-9 or questionnaire scores, so `model_df.csv`, `wav_inventory*.csv`,
`egemaps_*.csv`, `predictions_*.csv` and the `shap_*_full.csv` matrices are
generated locally and git-ignored, not committed.

**Consequence:** the notebooks cannot be run from a clone alone. Reproducing any
result requires your own MODMA access; run `MODMA_audio_processing.ipynb` first
to rebuild `model_df.csv`, then everything downstream works. The committed tables
let you read the results without rerunning anything.

## Setup

```bash
conda env create -f environment.yml

```

or with pip (Python 3.11):

```bash

```


## Running the analysis

Open any notebook from anywhere inside the clone, each starts with a bootstrap
cell that locates `scripts/` regardless of the kernel's working directory.

| # | Notebook | Produces | Needs raw audio? |
|---|---|---|---|
| 1 | `MODMA_audio_processing.ipynb` | `wav_inventory.csv`, resampled audio, `egemaps_features.csv`, `model_df.csv` | yes |
| 2 | `EDA.ipynb` | sample characteristics, distribution and correlation figures | metadata sheet only |
| 3 | `modeling_training.ipynb` | model comparison across feature sets, permutation tests | no |
| 4 | `dimensionality_reduction.ipynb` | comparison of three reduction strategies under nested CV | no |
| 5 | `interpretability.ipynb` | SHAP matrices, per-category importance tables and figures | no |
| 6 | `error_anaylsis.ipynb` | `predictions_*.csv`, residual plots, error-pattern tables | no |
| 7 | `robustness_experiments.ipynb` | perturbation experiments, `robustness_summary.csv` | for the noise cells |
| — | `audio_representation.ipynb` | figures illustrating what individual acoustic features measure | yes |

Steps 3–7 read `output/csv/model_df.csv`, which step 1 builds. Since that file is
not committed (see Data above), step 1 has to run first; after that the rest can
run in any order.

### Feature extraction

`MODMA_audio_processing.ipynb` pauses between resampling and feature parsing:
openSMILE runs in a terminal at that point, then the notebook continues.

```powershell
& "audio_lanzhou_2015/scripts/extract_egemaps.ps1"                    # clean audio
& "audio_lanzhou_2015/scripts/extract_all_conditions.ps1"             # robustness conditions
```

Both derive every path from their own location and are resumable. Rerunning
skips files already extracted.

## Conventions

**No absolute paths anywhere.** Every location comes from
`scripts/project_paths.py`, which derives `DATA_DIR` from its own file location.
Use the named constants (`INPUT_DIR`, `CSV_DIR`, `PLOTS_DIR`, `MODEL_DF_CSV`, …)
rather than writing path literals; add a new constant there if one is missing.

To keep the dataset or openSMILE outside the repository:

```
MODMA_DATA_DIR=/path/to/audio_lanzhou_2015
OPENSMILE_ROOT=/path/to/opensmile-3.0-win-x64
```

**Feature sets are defined once**, in `scripts/project_config.py`: `DEMO`,
`PSYCH`, `CLINICAL`, `ACOUSTIC` and the combined sets, along with the seed and the
shared repeated-CV scorer. PSQI is excluded from the modelled feature set via
`EXCLUDED_SCALES`; it remains in `PSYCH_ALL` so it is still available for
diagnostics and is never mistaken for an acoustic feature.

**Everything generated goes to `output/`.** Result tables to `output/csv/`,
figures to `output/plots/`.
